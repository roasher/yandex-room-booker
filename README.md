# yandex-room-booker

Бот для сотрудников Яндекса, который автоматически занимает переговорки под встречи,
в том числе когда возможность бронирования открывается в определённое время.

> Если вы пользуетесь ботом и он вам нравится, буду благодарен за
> ⭐ [звезду на GitHub](https://github.com/roasher/yandex-room-booker).

Для запуска нужен Java 21. Создайте `run.sh` на основе `run.sh.example`, настройте авторизацию
и нужные слоты, затем запустите `bash run.sh`.

`room-booker` — массив независимых конфигураций. Каждый элемент содержит `enabled`,
`meeting-name`, одну переговорку `room` и массив `slots` именно для этой встречи:

```json
{
  "room-booker-settings": {
    "time-zone": "Europe/Moscow"
  },
  "room-booker": [
    {
      "enabled": true,
      "meeting-name": "Йога",
      "room": "stroganov-yoga",
      "duration": "1h30m",
      "slots": [
        { "date": "2026-12-01", "time": "14:00" },
        { "day-of-week": 1, "time": "14:00", "duration": "1h" }
      ]
    },
    {
      "enabled": true,
      "meeting-name": "Музыка",
      "room": "lotte-music",
      "duration": "1h",
      "slots": [
        { "date": "2026-12-04", "time": "18:30" }
      ]
    }
  ]
}
```

Этот пример запускает три бронирования: два слота для йоги в Строганове и один для музыки в Лотте.
В массиве `slots` показаны оба варианта: `date` задаёт точную дату (1 декабря 2026 года),
а `day-of-week: 1` — ближайший понедельник после сегодня. В обоих случаях `time: "14:00"`
означает 14:00 по Москве. Замените дату или день недели и время на нужные вам значения.
Каждый элемент бронирует только свои слоты в своей переговорке. `enabled: false` отключает весь
элемент; отсутствующее `enabled` также означает отключение. Пустой массив не запускает бронирования.

`room` принимает ключ каталога из `src/main/resources/rooms.yml`, название, exchange или адрес
переговорки. Для каждой встречи с её переговоркой и слотами добавьте отдельный элемент в `room-booker`.

Для включённого элемента обязательны `meeting-name`, `room` и непустой массив `slots`.
В каждом слоте:

- `date` — конкретная дата `YYYY-MM-DD`, например `"2026-12-03"`.
- `day-of-week` — число от `1` (понедельник) до `7` (воскресенье).
- `time` — обязательное время `HH:mm` или `HH:mm:ss`.
- `duration` — длительность, например `30m`, `1h`, `1h30m`. Если не указана,
  используется `duration` из этого элемента `room-booker`.

Нужно указать хотя бы одно из `date` и `day-of-week`. Если указаны оба, дата должна соответствовать
дню недели. Без `date` выбирается ближайший указанный день **после сегодня**: в понедельник
`day-of-week: 1` выберет понедельник через неделю. Все даты вычисляются один раз при запуске
в настроенном часовом поясе. Каждый слот создаёт разовое бронирование.

Все значения `date` и `time` относятся к `room-booker-settings.time-zone` — по умолчанию
`Europe/Moscow`, то есть московскому времени. Например, `"date": "2026-12-03", "time": "18:30"`
означает 3 декабря 2026 года в 18:30 по Москве. Часовой пояс компьютера не меняет время встречи
или ожидания открытия лестницы. При необходимости другой пояс задаётся один раз для всех конфигураций.
Временные метки в префиксе логов могут использовать часовой пояс компьютера.

Общие настройки транспорта, часового пояса, авторизации и повторных попыток находятся
в отдельном объекте `room-booker-settings`. Например:

```json
{
  "room-booker-settings": {
    "time-zone": "Europe/Moscow",
    "slot-shift-step": "30m",
    "booking-open-buffer": "90s"
  },
  "room-booker": [
    {
      "enabled": true,
      "meeting-name": "Встреча",
      "room": "stroganov-yoga",
      "duration": "1h",
      "slots": [{ "date": "2026-12-03", "time": "18:30" }]
    }
  ]
}
```

Значения по умолчанию находятся в `src/main/resources/application.yml`.
Режим работы и авторизация задаются переменными окружения:

- `ROOM_BOOKER_BOOKING_MODE=browser` — веб-API календаря; в `YANDEX_CALENDAR_COOKIES`
  передаётся полный заголовок `Cookie` из браузера.
- `ROOM_BOOKER_BOOKING_MODE=api` — публичный API календаря; OAuth-токен передаётся
  в `YANDEX_CALENDAR_OAUTH_TOKEN`.

Пример настройки этих переменных и конфигурации бронирований — в `run.sh.example`.

Каждый слот обрабатывается независимо: ожидание или ошибка одного не останавливает остальные.
До ожидания открытия бронирования и первой попытки лестницы бот проверяет занятость переговорки
на весь целевой интервал. Проверка учитывает встречи других пользователей, в том числе созданные
администраторами заранее, вне обычного окна бронирования. Если встреча пересекает целевой слот,
бот сразу выводит её время и идентификатор и прекращает попытки для этого слота: забронировать его
можно только после отмены или переноса мешающей встречи. Остальные слоты продолжают обрабатываться.
Проверка выполняется при каждом запуске; после отмены встречи нужно запустить бот снова.
Свободный слот при запуске не гарантирует, что его не займут позже.

Собственное событие, найденное для продолжения лестницы, не считается препятствием. Встречи,
заканчивающиеся ровно в начале целевого слота или начинающиеся ровно в его конце, также не мешают.
Временные резервации без подтверждённого события не прекращают лестницу. Если получить занятость
не удалось, бот сообщает об ошибке и не начинает бронирование этого слота. Для режима `api` токену
нужен доступ к списку переговорок и их занятости (`calendar:free_busy.read` или `calendar:read_all`).

Для каждого слота бот строит прогрессивную лестницу, используя `bookable-ahead` и `max-duration` его переговорки.
Перед первой попыткой проверяются все включённые конфигурации. Пересекающиеся целевые слоты
в одной переговорке запрещены, в том числе в разных элементах массива и при использовании разных
названий одной переговорки. Временные ступени лестницы, занимающие другой целевой слот в этой же
переговорке, пропускаются. При перезапуске событие должно совпадать по названию встречи,
переговорке и времени ступени.

Если лестница не дошла до цели, ранее занятый промежуточный слот может остаться в календаре;
его время и идентификатор события будут указаны в логе ошибки. В конце выводится общее число
успешных бронирований.

В JSON-блоке `run.sh` можно отключать целые строки через `#`. Скрипт удаляет такие строки перед
передачей конфигурации; `#` внутри строкового значения сохраняется. Остальной JSON должен быть валидным.
